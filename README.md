# 播浪

中文名：**播浪** · 前缀 `livewave` · 端口 **6400 / 11400**

## 骨架

**互动事件入流 → 事件时间水位线推进 → 热度窗关闭发射 → 迟到修正/撤回 → 超迟旁路 → 旁路升格写新窗 → 窗输出与撤回/升格互证**

皮：直播间点赞/送礼互动。去皮是事件时间窗计算 + 允许迟到与撤回，不是直播运营后台 CRUD，不是点击会话空闲切开。

## 冒烟

```bash
docker compose up -d --build
# http://127.0.0.1:6400
# 入流 → 灌「准时热度样例」→ 水位线/热度窗 → 再灌「迟到修正样例」看撤回 →
# 灌「超迟到旁路样例」「旁路升格样例」→ 旁路匣点「升格」→ 贯验
```

## 主链对象

| 对象 | 作用 |
| --- | --- |
| 互动事件 | 带事件时/处理时的点赞送礼 |
| 水位线 | 每房事件时水位 + 允许迟到秒 |
| 热度窗 | 翻滚窗；开启累计，关闭发射 |
| 撤回单 | 已关闭窗被允许迟到事件修正 |
| 旁路匣 | 超允许迟到；状态 未处理/已升格 |
| 升格回执 | 旁路载荷写新窗的回执，UNIQUE(旁路编号) 防双计 |
| 窗贯验 | 窗合计 ↔ 事件合计 ↔ 末次撤回 ↔ 升格四方同态 |

## 旁路升格（口径取舍：只写升格时刻新窗）

两可行口径只贯彻其一，选定：**只写入升格时刻新窗**——目标窗键 = 升格处理时
事件时水位所在窗（水位必小于其窗止，故目标窗恒为开启窗）；**历史已关窗合计
禁止增加**，不写撤回单（撤回单专属迟到修正）；匣标「已升格」，事件命运 →
「已升格」。对偶口径「写回原窗键＋撤回/修正」不实现；两口径对「升格完成后
原窗键合计是否变大」结论相反，只读接口的 `原窗合计是否变` 字段使二者可区分
（本口径恒 `false`）。

硬约束（失败闭）：

- 匣状态与窗合计同成败：入流闸内单事务，任一环节失败整体回滚；
- 重复升格不双计：匣状态闸 + `升格回执.UNIQUE(旁路编号)`，重放只回执；
- 升格与入流/关窗扫描并发互斥：同持 `app.services.入流闸`，不得半截分叉；
- 站规 `允许升格=否` 时拒绝升格且无副作用。

接口：

- `POST /api/升格 {旁路编号}` → 回执（重复升格返回同一回执且 `重复=true`；站规禁止/状态分叉 → 409；旁路不存在 → 404）
- `GET /api/升格` → 只读列表：`旁路编号/原窗键/目标窗键/原窗合计是否变/valid`（valid 为匣/事件/回执/窗四方实时复核）
- `GET /api/升格?旁路编号=N` → 单条

夹具与验证（`backend/` 下）：

```bash
python3 tests/test_升格.py
# 夹具一 升格写新窗不改原窗（原窗合计不变、新窗可查）
# 夹具二 重复升格不双计
# 夹具三 并发升格×入流/关窗扫描无半截分叉
# 附   站规禁止 / 未知直播间旁路：失败闭
```

页面侧夹具：`fixtures/旁路升格样例.json`（P3 超迟旁路，水位停在 13:02:40，
升格目标窗 `房A|2026-11-22T13:02:00Z`）。
